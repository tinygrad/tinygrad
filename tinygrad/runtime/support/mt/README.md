# Moore Threads MT backend

The MT backend is a userspace driver for the MTT S80 (QUYUAN1, BVNC `35.4.1632.23`). It accesses the device through the existing USB/PCI interface and does not load a kernel module.

## Requirements

- MUSA Toolkit 4.3.0, used only for device compilation with `mcc`, `llvm-objcopy`, and `clang-offload-bundler`.
- The `mtfw-gen1.bin` firmware from the Linux MUSA 3.3.0 driver package. This is 32-bit Imagination META firmware for the GPU, not a host library.
- A supported MT USB/PCI device.

The MUSA userspace runtime and `libmtum` are not used or linked. Kernel text, launch resources, PDS programs, task/context state, MMU mappings, and CDM submissions are generated by tinygrad.

## Compiler and firmware setup

The compiler defaults to `/opt/musa`; set `MUSA_PATH` for a different toolkit location. Device kernels are compiled with `-O3`. MUSA 4.3 high-register spill kernels with live local arrays are recompiled with volatile local arrays to avoid incorrect spill results; ordinary kernels retain the normal optimization path.

Firmware is deliberately **not included in the tinygrad repository**. It is loaded from the first available location:

1. `MT_FIRMWARE`
2. `/lib/firmware/mthreads/mtfw-gen1.bin`
3. `/opt/musa/lib/firmware/mthreads/mtfw-gen1.bin`

The reference firmware was extracted without executing the installer from `MUSA_SDK_4.3.0.CC2.1.zip`, using the package `musa-sdk/MT_Linux_Driver_3.3.0/musa_3.3.0-server_amd64.deb`. Its SHA-256 is:

```text
1e8aba0686052f070d872da96118d407094ba604df54c6cbc159b2b325218c99
```

Install it with commands equivalent to:

```bash
dpkg-deb -x musa_3.3.0-server_amd64.deb /tmp/mt-driver
mkdir -p /opt/musa/lib/firmware/mthreads
cp /tmp/mt-driver/lib/firmware/mthreads/mtfw-gen1.bin /opt/musa/lib/firmware/mthreads/
sha256sum /opt/musa/lib/firmware/mthreads/mtfw-gen1.bin
```

The firmware remains subject to the MUSA SDK's license. The SDK and driver package must be obtained from Moore Threads; tinygrad does not redistribute them here.

`MT_BOOT_TIMEOUT` controls firmware startup timeout in seconds. `MT_TIMEOUT` controls submission and synchronization timeout in seconds.

## Validation

Hardware-independent tests are in `test/null/test_mt*.py`. Hardware regressions are in `test/test_tiny.py` and `test/runtime/test_mt_cache.py`.

```bash
DEV=MT python -m pytest test/test_tiny.py test/runtime/test_mt_cache.py -x -q
DEV=MT DEBUG=2 python -c 'from tinygrad import Tensor; print((Tensor([1.,2.,3.]) + Tensor([4.,5.,6.])).tolist())'
```

The current implementation targets MMU4 and generation-1 firmware only. Launches are serialized to preserve shared launch/MMU state. There is no copy queue, and double-precision kernels are not supported by the MUSA renderer. Launches requiring more than 1 GiB of spill storage are rejected before submission.
